title: local 에서 내부 전용(public false)을 overlay 가 강제하지 못한다
---
## 왜 위험한가
aws 는 public: false 를 internal ALB 로, gcp 는 gce-internal 로 만든다. local overlay 는 public 값과 무관하게
**같은 Traefik Ingress** 를 만든다. 그래서 "내부 전용" 은 명세가 아니라 클러스터 밖이 정한다.
- 터널(Cloudflare Tunnel 등)이 hostname 없이 catch-all 로 Traefik 을 가리키면, DNS 가 그 터널을 향하는 모든 호스트가 인터넷에 열린다.
- 라우터가 80·443 을 노드로 포트포워딩하면 Traefik 뒤의 모든 Ingress 가 공개된다.
- Service 를 NodePort 로 바꾸면 kube-proxy 가 nat PREROUTING 에서 바로 Pod 로 넘겨, 호스트 방화벽(UFW 등 INPUT 체인)으로는 막히지 않는다.
명세에는 이 경로들이 없어 정적 검사로 판정할 수 없다. 그래서 경고로 알리고 사람이 확인한다.

## 판정 기준
target.env 가 local 이고 network.ingress.public 이 false 이며 allowed_cidrs 가 비어 있다.
allowed_cidrs 가 있으면 렌더러 경고 INGRESS_CIDRS_NOT_ENFORCED 가 커밋을 막으므로 이 규칙은 보지 않는다.

## 고치는 법
자동으로 고치지 않는다. 배포 전에 사람이 확인한다:
1. 터널 ingress 는 공개할 hostname 만 나열하고 마지막 규칙을 404 로 둔다. 이 앱의 host 가 목록에 없어야 한다.
2. 라우터 포트포워딩이 Traefik 으로 향하면 내부 전용 앱은 같은 진입점에 두지 않는다.
3. NodePort 를 쓰지 않는다. 써야 하면 방화벽 INPUT 이 아니라 PREROUTING 단계에서 막고 외부에서 실제로 접속해 확인한다.
4. 확인은 내부망 밖(셀룰러 등)에서 curl 로 한다 — 내부에서 열리는지만 보면 노출 여부를 알 수 없다.
