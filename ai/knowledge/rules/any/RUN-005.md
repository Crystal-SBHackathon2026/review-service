## 왜 위험한가
overlay 는 컨테이너 정의를 통째로 바꾸므로 명세에 상한이 없으면 base 의 상한도 사라진다.
상한 없는 컨테이너는 메모리 누수·폭주 때 노드 메모리를 다 써서 같은 노드의 다른 Pod 까지 OOM 으로 죽이거나 축출되게 한다.
작은 노드에서는 한 Pod 가 노드 전체를 멈추게 할 수 있다.
AWS·GCP 는 기존 low 경고 정책을 유지한다. local 은 공유 노드 자원 보호를 위해 medium 으로 검토하고 자동 수정 대상으로 삼는다.

## 판정 기준
runtime.resources 의 cpu_limit 또는 memory_limit 이 없다.

## 고치는 법
자동 수정 가능. 비어 있는 상한을 gitops base rollout.yaml 과 같은 값(cpu_limit 250m, memory_limit 128Mi)으로 채운다.
앱이 그보다 많이 쓰면 OOMKilled 로 재시작되므로, 배포 후 실제 사용량을 보고 값을 올린다.
기존 요청값과 이미 선언한 상한은 바꾸지 않는다. 기본 상한이 요청값보다 작으면 자동 패치를 거부하고 사람이 상한을 정한다.
요청값보다 작은 기본 상한은 승인용 권장값에서도 제외한다. 안전한 기본값이 없으면 일반 승인만으로 진행하지 않고 요청량 이상의 상한 입력을 요구한다.
사람이 직접 입력하거나 이전 검토에 저장된 권장값을 사용하는 경우도 동일하게 검사한다. `use_recommendations: false`로 상한 생략을 명시 승인하는 기존 선택은 유지하지만, 선언한 상한이 요청값보다 작은 명세는 승인할 수 없다.
