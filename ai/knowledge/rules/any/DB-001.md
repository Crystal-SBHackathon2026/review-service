title: 데이터가 있는 DB 의 엔진 변경
---
## 왜 위험한가
DB 엔진(postgres → mysql 등)을 바꾸면 새 엔진은 빈 DB 로 시작한다. 기존 데이터는 자동으로 옮겨지지 않고,
스키마·타입·SQL 방언이 달라 덤프를 그대로 넣을 수도 없다. 배포만 바꾸면 앱은 빈 DB 를 보거나 시작에 실패한다.
되돌리려 해도 변경 이후 새 DB 에 쓰인 데이터가 이전 DB 에는 없으므로 되돌릴 수 없는 변경이다.

## 판정 기준
baseline(이전 승인 배포)의 database.engine 이 none 이 아니고 지금과 다르며, baseline.facts.database_has_data 가
false 로 확인되지 않았다. 데이터 유무를 모르면(null) 데이터가 있다고 본다 — 모르는 상태로 자동 변경하지 않는다.

## 고치는 법
자동 수정하지 않는다(사람 확인, 사유 IRREVERSIBLE). 선택지는 둘이다.
1. 이전 엔진을 유지한다 — deploy_spec 의 database.engine·version 을 baseline 값으로 되돌린다.
2. 엔진을 바꿔야 하면 사람이 이전 계획을 승인한다: 쓰기 중지 → 덤프 → 변환(pgloader 등) → 복원 → 건수 검증 → 전환.
   이전 DB 는 검증이 끝날 때까지 지우지 않는다.
