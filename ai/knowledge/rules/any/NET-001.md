title: 공개 진입점에 TLS 가 없다
---
## 왜 위험한가
인터넷에 열린 HTTP 는 로그인 쿠키·토큰이 평문으로 오간다. 다만 도메인·인증서가 없는 개발 단계에서는 바로 켤 수 없어
경고(low)로만 둔다. low 는 사람 확인 조건에서 빠지므로 이것만 있으면 pass 이고 보고서에 경고로 표시된다.

## 판정 기준
network.ingress.public 이 true 이고 tls 가 false 다. 또는 GCP에서 network.service.public 이 true인
LoadBalancer Service로 HTTP 80을 공개한다. 현재 Service 명세에는 TLS 종료 설정이 없다.

## 고치는 법
자동 수정하지 않는다. Ingress는 도메인을 정하고 network.ingress.host 를 채운 뒤 tls: true 로 바꾼다.
공개 LoadBalancer Service는 도메인·인증서와 별도의 TLS 종료 구성이 필요하다. 명세의 type이나 public 값을
자동으로 바꾸어 해결하지 않으며, preview Service는 내부에 유지한다.
인증서 준비 방법은 환경마다 다르다 (aws·gcp·local 문서 참고).
