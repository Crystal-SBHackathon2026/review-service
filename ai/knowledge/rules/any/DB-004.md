## 왜 위험한가
requirements.persistence 는 "재배포 뒤에도 데이터가 남아야 한다"는 선언이다. 그런데 DB·persistent 볼륨·버킷이 모두 없으면
앱이 쓰는 파일은 컨테이너 쓰기 계층에 남고, Pod 가 다시 만들어지는 순간(재배포·재시작·노드 이동) 사라진다.
배포 직후 기능 검사는 통과하므로 첫 재시작 전까지 드러나지 않는다.

## 판정 기준
requirements.persistence 가 true 인데 database.engine 이 none 이고, storage.volumes 에 persistent: true 볼륨도 storage.buckets 도 없다.

## 고치는 법
자동 수정하지 않는다(사람 확인) — 저장소를 고르는 일은 앱 코드와 맞물린다.
앱이 데이터를 어디에 쓰는지 확인해 DB(database.engine·placement)를 선언하거나, persistent 볼륨을 추가하고 앱이 그 mount_path 에 쓰게 한다.
데이터 보존이 실제로 필요 없다면 requirements.persistence 를 false 로 바꾼다.
